## 수정 제안 — 아직 적용하지 않음

### 1. Responses 문자열 input 변환

재현: POST /v1/responses에 `{"input":"Reply with exactly OK."}`.
실제 응답: HTTP 400, `{"detail":"Input must be a list"}`.
Responses 호환 형식의 문자열 입력을 백엔드에 그대로 보내고 있어 실패합니다.
배열 형식의 입력은 통과했습니다.

제안: 문자열 input을 사용자 메시지와 input_text 콘텐츠 배열로 결정적으로 변환.
문자열 내용과 기존 배열 입력은 유지. 같은 입력의 반복 변환과 실제 호출을 함께 검증.
README의 간단한 Responses 예제를 그대로 실행하는 사용자에게 영향을 줍니다.

### 2. 잘못된 JSON의 오류 응답 통일

재현: Content-Type application/json, 본문 `{`.
실제 응답: HTTP 400이지만 본문은 일반 텍스트
`Failed to parse the request body as JSON: EOF while parsing an object at line 1 column 1`.
OpenAI 호환 error 객체가 아니어서 클라이언트의 오류 해석이 일관되지 않을 수 있습니다.

제안: HTTP JSON 추출 실패를 API 경계에서 공통 JSON error 객체로 변환.
정상 요청 처리와 백엔드 오류 전달은 유지.
